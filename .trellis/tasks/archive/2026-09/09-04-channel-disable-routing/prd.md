# 渠道禁用阻断分组选路

## Goal

让渠道 `Enabled=false` 成为真实的选路开关: 禁用渠道后, 引用该渠道授权的分组成员不再参与转发; 分组的可选成员全部因渠道禁用而不可选时, 请求立即向客户端报错, 而不是挂起等待或继续请求上游。

现状缺陷: `Channel.Enabled` 仅影响分组页候选的 `Available` 展示(`internal/op/channel.go:334`)与分组读取快照(`internal/op/group.go:292`), 转发链路完全不读取它——`ChannelGrantGet` 只校验凭据启停(`internal/op/channel.go:304`), `pickGroupItem` 也不看渠道状态(`internal/relay/route.go:68`), `internal/relay/route.go:67` 注释承诺的"禁用后不参与选路"与实现不符。

## Background

- 每轮选路: `GroupGetByName` 取原始成员 → `pickGroupItem` 按模式挑成员 → `ChannelGrantGet` 校验授权可转发 → `ChannelGet` 取渠道 → 请求上游(`internal/relay/handler.go:82-126`)。
- 成员不可选的既有语义: 空组、全员冷却、授权缺失、凭据停用、渠道删除均为等待重试(等待配置修复或冷却到期), 不向客户端报错。
- 用户决策(已确认): 渠道禁用是硬开关, 区别于上述软等待; `/v1/models` 与 API Key 面板维持现状照常列出全部分组(与空组口径一致); 统计保留。

## Requirements

### R1 渠道禁用过滤选路成员

- 故障转移模式: 成员所属渠道被禁用时, 该成员不参与本轮及后续选路(等同不存在), 其余成员正常按优先级承接。
- 手动模式: 人工指定的成员所属渠道被禁用时, 该成员不可选(手动模式不回退到其他成员, 维持"只使用人工选中的成员"语义)。

### R2 全员因渠道禁用不可选时立即报错

- 分组成员非空且可选成员全部因渠道禁用被过滤时, 请求立即以协议错误体返回客户端并终态(沿用 `markFailed` + 协议错误转换的请求级失败模式), 不等待、不重试、不请求上游。
- 故障转移模式的判定范围是全部分组成员; 手动模式的判定范围仅人工指定的成员。
- 错误响应需让客户端明确区分这是"渠道被禁用"而非"模型名错误"。

### R3 既有语义不变

- 空组、全员冷却、授权缺失、凭据停用、渠道删除: 维持现有等待重试行为。
- 混合分组(部分成员在被禁渠道上): 请求由其余成员正常承接, 不报错。
- 混合不可用(部分成员渠道禁用、其余成员凭据停用等): 按既有语义处理等待, 不因渠道禁用部分而提前报错。
- `/v1/models`(`internal/server/handlers/model.go:58`)与 API Key 面板(`internal/server/handlers/apikey.go:110`)继续列出全部分组, 不因渠道禁用隐藏。
- 渠道统计照常保留, 禁用不删除任何数据。
- 禁用/启用即时生效(经 `ChannelEnabled` 同步更新渠道缓存, `internal/op/channel.go:215`), 无需重启。

### R4 前端无需变更

分组页成员可用性与分组页候选的 `Available` 已按 `channel.Enabled && channelKey.Enabled` 计算, 语义随本任务自动变准, 不改前端代码。

## Acceptance Criteria

- [ ] AC1 渠道 A 被禁用后, 分组(故障转移)成员含 A 与启用渠道 B 时: 请求由 B 承接成功, 不再请求 A 的上游。
- [ ] AC2 分组全部成员均指向被禁渠道时: 请求立即收到协议错误体(非挂起), 错误信息表明渠道被禁用; 请求状态终态为失败。
- [ ] AC3 手动模式指定成员指向被禁渠道时: 请求立即收到同一错误, 不回退其他成员。
- [ ] AC4 空分组请求: 维持现状挂起等待(回归不破坏)。
- [ ] AC5 成员凭据停用(渠道启用)时: 维持现状等待语义, 不立即报错(回归不破坏)。
- [ ] AC6 重新启用渠道后, 后续请求无需重启即恢复由该渠道成员承接。
- [ ] AC7 `/v1/models` 在渠道禁用前后返回一致(含全员被禁的分组)。

## Out of Scope

- 不隐藏 `/v1/models` / API Key 面板中的模型。
- 不改动空组行为。
- 不改动凭据(ChannelKey)停用的等待语义。
- 不引入渠道自动禁用/探活联动。
- 不改前端代码与接口形状。
